# 提示词管理功能需求文档

## 1. 需求背景

### 1.1 业务背景
当前 CCToggle 项目支持多 Agent 框架（Codex、Claude、Gemini、OpenClaw）的供应商管理、Skill 管理和 MCP 管理。在实际使用中，用户需要为不同的 Agent 配置专属的提示词（Prompt），以优化 AI 的响应质量和行为模式。

### 1.2 现状分析
- **已有功能**：Skill 管理、MCP 管理、供应商管理、会话管理
- **缺失功能**：提示词管理入口，用户无法集中管理各 Agent 的提示词配置
- **当前入口位置**：TabBar 中 Skill 管理按钮位于右侧功能区

---

## 2. 需求目标

### 2.1 核心目标
在首页 TabBar 的 Skill 管理按钮**左侧**增加「提示词管理」入口，提供统一的提示词配置和管理界面。

### 2.2 设计原则
- **一致性**：与现有 Skill 管理页面的交互模式保持一致
- **可扩展性**：支持多种 Agent 框架的提示词配置
- **易用性**：提供直观的提示词编辑和预览功能

---

## 3. 功能设计

### 3.1 功能入口
**位置**：TabBar 右侧功能区，Skill 管理按钮左侧

**图标**：建议使用 `DocumentTextOutline` 或 `ChatbubbleEllipsesOutline`（来自 @vicons/ionicons5）

**交互**：点击后跳转到 `/prompts` 路由

### 3.2 页面结构

```
提示词管理页面
├── 顶部导航
│   ├── 返回按钮 (←)
│   └── 页面标题 "提示词管理"
├── Tab 切换
│   ├── 按 Agent 分类（Codex / Claude / Gemini / OpenClaw）
│   └── 或 按用途分类（系统提示词 / 用户提示词 / 场景提示词）
└── 内容区域
    ├── 提示词列表
    │   ├── 提示词卡片
    │   │   ├── 名称
    │   │   ├── 预览内容（截断显示）
    │   │   ├── 关联 Agent 标签
    │   │   └── 操作按钮（编辑 / 删除 / 复制）
    │   └── 新建提示词按钮
    └── 提示词编辑器（右侧或弹窗）
        ├── 名称输入
        ├── 内容编辑区（支持 Markdown）
        ├── Agent 选择（多选）
        ├── 变量插入（{{变量名}}）
        └── 保存 / 取消按钮
```

### 3.3 核心功能

#### 3.3.1 提示词 CRUD
- **创建**：新建提示词，支持 Markdown 格式
- **读取**：查看提示词列表和详情
- **更新**：编辑提示词内容和配置
- **删除**：删除不需要的提示词

#### 3.3.2 Agent 框架适配
支持以下 Agent 框架的提示词配置：

| Agent 框架 | 提示词格式 | 特殊配置 |
|------------|----------|----------|
| **Codex** | OpenAI 兼容格式 | 支持 `personality` 字段、`reasoning_effort` 配置 |
| **Claude** | Anthropic 格式 | 支持 `system` 提示词、`temperature` 配置 |
| **Gemini** | Google AI 格式 | 支持 `safety_settings`、`generation_config` |
| **OpenClaw** | OpenAI 兼容格式 | 支持自定义 `api_protocol` |

#### 3.3.3 提示词模板
提供预设模板：
- **通用助手**：基础对话模板
- **代码专家**：编程辅助模板
- **写作助手**：文案创作模板
- **翻译专家**：多语言翻译模板
- **自定义模板**：用户可创建和保存自定义模板

#### 3.3.4 变量系统
支持动态变量插入：
- `{{current_file}}` - 当前文件路径
- `{{language}}` - 编程语言
- `{{user_input}}` - 用户输入
- `{{context}}` - 上下文信息
- `{{timestamp}}` - 时间戳

### 10.3 Markdown 解析器选型（轻量方案）

#### 推荐方案：marked（最轻量 ⭐）

**简介**：高性能 Markdown 解析器，体积小、速度快

**安装命令**：
```bash
pnpm add marked
```

**特点**：
- ✅ **极轻量**：gzipped 仅 ~7KB
- ✅ **零依赖**：无额外依赖
- ✅ **速度快**：解析性能优异
- ✅ **GFM 支持**：支持 GitHub Flavored Markdown
- ✅ **安全**：支持 HTML 转义
- ✅ **稳定**：npm 周下载量 50M+

**使用示例**：

```javascript
// src/utils/markdown.js
import { marked } from 'marked';

// 配置选项
marked.setOptions({
  gfm: true,        // 启用 GitHub Flavored Markdown
  breaks: true,     // 换行符转为 <br>
  sanitize: false,  // 不转义 HTML（需自行处理 XSS）
});

export function renderMarkdown(content) {
  return marked(content);
}
```

#### 备选方案：snarkdown（极简方案）

**简介**：极简 Markdown 解析器，适合只需要基础语法的场景

**安装命令**：
```bash
pnpm add snarkdown
```

**特点**：
- ✅ **极小体积**：gzipped 仅 ~1KB
- ✅ **零依赖**
- ✅ **快速**
- ❌ 功能有限：仅支持基础语法（粗体、斜体、链接、图片、代码、列表）
- ❌ 不支持表格、任务列表等高级语法

**使用示例**：

```javascript
import snarkdown from 'snarkdown';

export function renderMarkdown(content) {
  return snarkdown(content);
}
```

---

#### 方案对比

| 特性 | marked | snarkdown |
|------|--------|-----------|
| **体积（gzip）** | ~7KB | ~1KB |
| **GFM 支持** | ✅ | ❌ |
| **表格支持** | ✅ | ❌ |
| **代码高亮** | 需扩展 | ❌ |
| **任务列表** | ✅ | ❌ |
| **安全性** | 需配置 | 需自行处理 |
| **适用场景** | 通用 | 极简需求 |

---

#### 推荐选择

**首选：marked**
- 理由：功能完整、体积小（~7KB）、支持 GFM、性能优秀
- 适合：提示词编辑器的预览功能

**备选：snarkdown**
- 理由：极致轻量（~1KB），适合仅需基础语法的场景
- 适合：简单文本预览，不需要表格、任务列表等功能
